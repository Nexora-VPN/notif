# Nexora Notif

Notif 向 Nexora 面板的用户通知其账户情况：即将到期、流量即将用完、续期、增加流量，以及管理员自己的消息——通过 Telegram、Bale、Soroush Plus、Rubika、短信、电子邮件、ntfy 或任意 HTTP API 发送。

**一条通知，一次送达。** 通知只写一次，按您设定的顺序交给用户的渠道。只有当前渠道无法送达时才尝试下一个：用户在该渠道没有地址、渠道拒绝（机器人被屏蔽、号码不存在）或连续三次出错。因此付费短信只在免费渠道无法送达时才发出，也没有人会重复收到同一条通知。

Notif 与所有 Nexora 插件一样是独立程序：有自己的服务和数据库，通过权限受限的令牌和面板签名的事件读取面板。所有即时通讯的关联都保存在面板中账户的联系信息里，其他插件也能看到。

## 安装

在面板中：**服务 → 插件 → 浏览 → Nexora Notif → 安装**。面板会询问清单中的问题——端口（8097）、数据库（SQLite，或带连接字符串的 PostgreSQL）、首个管理员的名称和密码——然后通过 SSH 把 Notif 安装到面板所在的服务器或另一台服务器，或者给出一条命令由您手动执行：

```sh
sh install.sh --method docker --opt port=8097 --opt admin_password=… \
  --panel-url https://panel.example --claim-code …
```

`--method script` 用 systemd 代替 Docker 运行程序。同一条命令可就地更新；`--uninstall [--purge]` 用于卸载。Notif 通过健康检查后，面板会注册它并请您批准其权限：读取账户，以及把即时通讯的关联写入账户的联系信息。

用首个管理员登录 `http://<host>:8097`，并在**安全**中开启两步验证。忘记的密码可在服务器上重置：`notif admin reset-password -user admin -pass …`。

## 渠道

**渠道**按回退顺序列出：第一个能送达用户的渠道负责发送。用箭头调整顺序；可以停用而不删除。每个渠道显示今日和本月的发送量。**测试**按账户名向一个账户发送测试通知。

### Telegram、Bale 和 Soroush Plus

三者使用同一种 Bot API。在各自的 BotFather 创建机器人并填入令牌。**请为 Notif 单独创建机器人**：一个机器人的更新只能由一个程序读取，Shop 或其他工具已在使用的令牌不能共用（若如此，渠道会提示）。

- **Telegram** —— 位于伊朗或中国的服务器无法访问 `api.telegram.org`：请设置**代理**（`socks5://host:port`），或把 Bot API 镜像填为 API 地址。
- **Bale** —— Bale 用自己的 Markdown 显示所有消息，并会限制向非对话中用户发消息的机器人。其付费**商业 API** 专用于通知：Bale 商业账户充值后在渠道中开启即可。
- **Soroush Plus** —— 与 Telegram 相同，地址为 `api.splus.ir`。

### Rubika

Rubika 有自己的 Bot API，Notif 已支持。它可能拒绝伊朗境外的服务器：请为渠道设置位于伊朗的代理，或填写伊朗境内中转的地址。

### 将用户关联到机器人

机器人只能给已启动它的人发消息。用户把**订阅链接**（或仅其令牌）发给机器人，或者发送在**账户**页面中该用户的**绑定码**，即可关联账户——对 Telegram，该页面还提供附带绑定码的链接，点一下即可完成。聊天 id 会写入面板中该账户的联系信息（`telegram_id`、`bale_id`、`soroush_id`、`rubika_id`）；若联系信息中没有语言，还会以 `lang` 记录用户在即时通讯中的语言。`/stop` 取消关联；屏蔽机器人的用户会被自动取消关联，其通知改走下一个渠道。十分钟内五次错误尝试会暂时锁定该聊天。

### 短信：Kavenegar 和 Faraz SMS

两者都通过服务线路上**已审核的模板**发送——这类短信也能送达屏蔽了广告短信的号码。在服务商后台编写模板并通过审核，然后告诉 Notif 每个变量对应什么，每行一个：

- **Kavenegar**：模板名称，以及 `token={name}`、`token2={days}` …… Kavenegar 的变量为 `token`、`token2`、`token3`（不含空格——Notif 会把空格换成连字符）、`token10`（最多 5 个空格）和 `token20`（最多 8 个）。模板示例：
  `%token，您的账户将在 %token2 天后（%token3）到期。`
- **Faraz SMS**：模板代码和线路号码，按模板中的名称填写变量（`name={name}`），以及**每个变量在模板中的长度**（`name=20`）。值比模板规定的长时，Faraz 会把消息留待人工审核却仍回报“已发送”——所以 Notif 会把每个值截断到其长度。

电话取自联系信息中的 `phone`，书写方式不限（`+98 912…`、`0912…`、`912…`、波斯数字）。短信服务商的条款可能禁止宣传 VPN；Notif 的通知是账户通知，其默认文字也不含这个词。

### 电子邮件

任意 SMTP 服务器：地址、端口（587 用 STARTTLS，465 用 TLS）、用户和密码、发件人。邮件为纯文本。**请使用自己的域名并配置 SPF、DKIM 和 DMARC 发送**：QQ 邮箱、163、Mail.ru、Yandex 和 Gmail 会拒收或隐藏无法验证的邮件。地址取自联系信息中的 `email`。

### ntfy

ntfy 是用户自行安装的推送应用，每人订阅自己的主题。在**账户**页面中为用户开启 ntfy：Notif 会生成无法猜到的主题，以 `ntfy` 保存在联系信息中，并显示需要交给用户的地址（`https://ntfy.sh/notif-…` 或您自己的服务器）。知道地址的人都能读取——只交给该用户。在没有 Google 服务的国产安卓手机上，用户需在应用中开启 **instant delivery**；在 iOS 上，自建服务器需把 `upstream-base-url` 设为 `https://ntfy.sh`。

### 通用 HTTP 渠道

任何提供 HTTP API 的服务：地址、方法、请求头和正文，均为基于通知的模板，再加上联系信息中存放用户在该服务地址的字段（`phone`，或您自定义的键，如 `vk_id`）。服务商的密钥填在**密钥**中，以 `{{.Secret}}` 读取，绝不会出现在记录里。正文可以是 JSON、表单（`name=value`，每行一个）或无；支持 HTTP Basic 认证、为失败也返回 200 的服务商准备的**成功判断**，以及用于私有证书的 CA 证书。

变量：`{{.Text}}`、`{{.Title}}`、`{{.Address}}`、`{{.Name}}`、`{{.Secret}}`、`{{.ID}}`（每条通知固定的数字——VK 的 `random_id`）、`{{.Key}}`（Matrix 的事务 id）、`{{.Vars.days}}` 及其他通知变量；函数 `json`、`urlquery`、`e164`（`+86138…`）、`msisdn`（`86138…`）和 `iran`（`0912…`）。

**预设**可为 SMS.ru、SMSC、SMS Aero、MTS Exolve、VK、LINE、Matrix 和 Pushover 填好全部设置——替换大写字母部分即可。WhatsApp 可通过您自选的中介在此渠道上使用；Notif 不提供非官方 WhatsApp 客户端。

## 通知

**通知**页面包含您的**时间安排**——到期前几天（如 `5, 1`）和流量用到多少比例（如 `80, 95`）时提醒用户——以及每种通知的开关：

- **按您的安排**：即将到期、流量即将用完。每条只发送一次，账户续期、增加流量或进入新周期后重新生效。
- **面板通知时**：续期、到期、流量用完、账户创建（附订阅链接）、代理商额度用完、恢复使用、套餐开始、订阅已添加、设备上限、删除。
- **管理员更改账户时**：增加流量、更改到期日、流量重置、手动停用或启用。这些会等待一分半钟：如果更改其实是续期，就由续期通知代替。

**文字**按语言打开通知的文字；当某个渠道需要不同文字（如较短的短信）时，还可按渠道类型设置。留空的字段沿用默认文字。点击变量即可插入：`{name}`、`{expiry}`、`{days}`、`{traffic_total}`、`{traffic_used}`、`{traffic_left}`、`{percent}`、`{added}`、`{sub_url}`、`{group}`。预览会用示例账户显示效果。波斯语默认使用伊朗历（也可在**日期**中为所有语言统一日历）。

用户的语言取其联系信息中的 `lang`（fa、en、ru 或 zh），否则取**设置**中的语言。**静默时段**（设置）会把通知留到时段结束——不会丢弃；标记为**紧急**的通知不受限制。

## 消息

**消息**可发给一个或多个账户，或发给由面板自身筛选条件选出的分组：分组、状态、几天内到期、已用流量、所有者、模板、节点、搜索。**统计**在发送前显示匹配的账户数、每个账户将走哪个渠道、其中多少是短信、多少没有任何渠道可达，并显示第一个账户将看到的消息内容。**发送**会再确认一次并注明短信数量。消息在后台按各渠道速率发出；尚未发出的可以取消；报告显示已送达的数量、经由哪个渠道以及失败情况。账户页面会列出发给该账户的内容。

## 伊朗、俄罗斯和中国

| | 开启 VPN 时可达 | 关闭 VPN 时可达 |
| --- | --- | --- |
| 伊朗 | Telegram 及其他所有渠道 | Bale、Soroush Plus、Rubika、短信、电子邮件 |
| 俄罗斯 | Telegram、电子邮件、ntfy | 电子邮件（Mail.ru 和 Yandex 在移动网络白名单模式下仍可访问）；拥有俄罗斯法人的运营者可用短信 |
| 中国 | Telegram、ntfy、电子邮件 | 电子邮件（QQ 邮箱、163） |

好的顺序是把用户常看的免费渠道放在前面，把短信或电子邮件放在最后：在伊朗为 Telegram → Bale → 短信；在俄罗斯和中国为 Telegram → ntfy → 电子邮件。俄罗斯会对宣传绕过封锁方法的行为罚款（38-FZ）：请让通知只涉及账户——默认文字不含价格、优惠或 VPN 一词。俄罗斯短信服务商只把发件人名称授予俄罗斯公司或个体经营者；中国的短信通道需要在中国大陆注册的公司——Notif 不内置任何此类服务商。

## 记录与隐私

**发送记录**列出每次送达及各渠道的尝试和回应。已完成的送达连同文字会在**设置**中规定的天数（默认 90 天）后删除。Notif 保存账户名称、联系信息、到期日和流量的副本，用于判断和撰写通知；订阅链接的秘密部分只以哈希形式保存。

## 备份

使用 SQLite 时，Notif 每天把数据库复制到 `<data>/backups`，保留最近七份。手动：`notif backup -o notif.db`；在 Notif 停止时执行 `notif restore -i notif.db`（被替换的数据库会保留在旁边）。使用 PostgreSQL 时请用 `pg_dump` 备份。

## 出现问题时

- **机器人渠道提示其更新正被另一个程序读取** —— 该令牌已在别处使用（Shop、Webhook）：请为 Notif 创建独立的机器人。
- **记录中出现“无地址”** —— 用户的联系信息中没有该渠道的地址；改走下一个渠道。
- **“没有渠道送达该用户”** —— 所有渠道都已尝试；记录中的各次尝试说明了失败原因。
- **某个账户没有任何通知入队** —— 没有已开启的渠道拥有其地址：请关联机器人，或在联系信息中添加电话或邮箱。
